---
title: Install Bora
description: Install, update, and verify Bora on Linux, macOS, and Windows.
---

Bora publishes stable-channel binaries for Linux, macOS, and Windows. Windows is generally available, with documented platform-specific limitations and ongoing fixes.

## Install

On Linux or macOS, run:

```bash
curl -fsSL https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.sh | sh
```

On Windows, run:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 | iex"
```

If endpoint security blocks that fileless PowerShell command, open Command Prompt and run:

```cmd
curl.exe -fsSLo install.ps1 https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 && powershell -ExecutionPolicy Bypass -File install.ps1 && del install.ps1
```

The installer downloads the release binary for your platform and places it on your PATH (`~/.local/bin` by default on Linux/macOS, override with `HERDR_INSTALL_DIR`). New direct installs use the stable update channel. Existing Windows preview installs stay on preview until you switch them with `bora channel set stable`. On Windows, PATH points to the active versioned release directory; the installer also updates the `current` and stable `bin` compatibility aliases, so updates do not need to overwrite a running `bora.exe`.

## Install with Nix

If you already use Nix, the flake in this repository builds Bora from source:

```bash
nix run github:aryrabelo/bora-herdr-ada
nix build github:aryrabelo/bora-herdr-ada
nix profile install github:aryrabelo/bora-herdr-ada
```

The flake also exposes a development shell:

```bash
nix develop github:aryrabelo/bora-herdr-ada
```

Use the same Nix workflow to update Bora. For a profile install, list your profile entries and upgrade the entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Bora is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update bora
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/aryrabelo/bora-herdr-ada/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `bora-linux-x86_64` |
| Linux aarch64 | `bora-linux-aarch64` |
| macOS Intel | `bora-macos-x86_64` |
| macOS Apple silicon | `bora-macos-aarch64` |
| Windows x86_64 | `bora-windows-x86_64.zip` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x bora-linux-x86_64
mv bora-linux-x86_64 ~/.local/bin/bora
```

### Windows archive

Stable releases and preview prereleases both include `bora-windows-x86_64.zip`. The archive contains `bora.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `bora.exe`.

## Verify

Start Bora:

```bash
bora
```

If your shell cannot find `bora`, restart the terminal or check that the install directory is on your PATH.

## Update

Bora checks for new releases and notifies you in the app. You can update manually:

```bash
bora update
```

Use `bora update` only for installs managed by Bora's own installer. Update Nix installs through Nix instead.

Direct installs on Linux, macOS, and Windows use the stable update channel by default. To opt into preview builds from `main`, set the channel:

```bash
bora channel set preview
```

Switch a direct install back to stable the same way:

```bash
bora channel set stable
```

For direct installs, changing channels checks the selected channel and installs its latest binary. If that update fails, run `bora update` to retry from the configured channel.

Preview builds are regularly published GitHub prereleases from the current development branch. They are useful when you want fixes before the next stable release, but they can regress. Nix installs do not use the preview channel.

Stable is the recommended channel for normal Windows use. Preview receives fixes sooner but can regress, so opt in only when you want that tradeoff. Existing Windows preview installs remain on preview until you switch them explicitly. If an older preview build rejects `bora channel set stable`, run `bora update` once on preview, then retry the channel switch.

By default, `bora update` installs the new binary and leaves endpoint-generation-1 servers and their pane processes running. Start Bora again to reconnect with the updated client. Client-only changes work immediately. A new server-side action stays unavailable until that server is updated and restarted; the client shows a notice instead of disconnecting. Servers from before endpoint generation 1 need one final stop during update.

To opt into experimental live server handoff for supported running sessions, run:

```bash
bora update --handoff
```

When both servers support agent-status transfer, live handoff preserves hook-reported agent status until the next report arrives. Handoff from an older server can temporarily show a running agent as idle.

Live handoff does not apply to Nix package-manager updates. For those installs, update with Nix, then run Bora again to reconnect with the updated client. The compatible old server keeps running. Restart it later with `bora server stop` or `bora session stop <name>` only when you want server-side changes from the new release.

## Requirements

Stable-channel binaries are available for Linux, macOS, and Windows x86_64. See [Windows support](/docs/windows-beta/) for supported workflows and known limitations. Windows ARM64 runs the x86_64 build under Windows emulation.
