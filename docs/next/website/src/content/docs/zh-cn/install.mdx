---
title: 安装 Bora
description: 在 Linux、macOS 和 Windows 上安装、更新和验证 Bora。
---

Bora 为 Linux、macOS 和 Windows 提供稳定通道二进制文件。Windows 支持已正式发布,并记录了平台专用的已知限制和持续修复。

## 安装

在 Linux 或 macOS 上运行:

```bash
curl -fsSL https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.sh | sh
```

在 Windows 上运行:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 | iex"
```

如果端点安全软件阻止该无文件 PowerShell 命令，请打开命令提示符并运行：

```cmd
curl.exe -fsSLo install.ps1 https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 && powershell -ExecutionPolicy Bypass -File install.ps1 && del install.ps1
```

安装器会下载适合你平台的发布二进制文件并放到 PATH 上(Linux/macOS 默认为 `~/.local/bin`,可用 `HERDR_INSTALL_DIR` 覆盖)。新的直接安装默认使用稳定更新通道。现有的 Windows 预览安装会继续留在预览通道,直到你运行 `bora channel set stable`。在 Windows 上,PATH 指向当前带版本号的发布目录;安装器还会更新 `current` 和稳定的 `bin` 兼容别名,因此更新时不需要覆盖正在运行的 `bora.exe`。

## 用 Nix 安装

如果你已经在用 Nix,本仓库中的 flake 会从源码构建 Bora:

```bash
nix run github:aryrabelo/bora-herdr-ada
nix build github:aryrabelo/bora-herdr-ada
nix profile install github:aryrabelo/bora-herdr-ada
```

flake 还提供一个开发 shell:

```bash
nix develop github:aryrabelo/bora-herdr-ada
```

更新时使用你安装 Bora 的同一套 Nix 工作流。对于 profile 安装,列出 profile 条目并升级该条目:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

如果 Bora 是你自己 flake 的一个 input,更新该 input 并重建你的系统、Home Manager 或开发环境:

```bash
nix flake update bora
```

## 手动下载

也可以从 [GitHub releases](https://github.com/aryrabelo/bora-herdr-ada/releases) 下载二进制文件。

选择匹配你系统的产物:

| 系统 | 产物 |
| --- | --- |
| Linux x86_64 | `bora-linux-x86_64` |
| Linux aarch64 | `bora-linux-aarch64` |
| macOS Intel | `bora-macos-x86_64` |
| macOS Apple silicon | `bora-macos-aarch64` |
| Windows x86_64 | `bora-windows-x86_64.zip` |

在 Linux 或 macOS 上,赋予可执行权限并移动到 PATH 上的某个位置。

```bash
chmod +x bora-linux-x86_64
mv bora-linux-x86_64 ~/.local/bin/bora
```

### Windows 压缩包

稳定版发布和预览版预发布都会包含 `bora-windows-x86_64.zip`。压缩包包含 `bora.exe` 及其应用本地 ConPTY 运行时。请保留完整的解压目录,不要只复制 `bora.exe`。

## 验证

启动 Bora:

```bash
bora
```

如果 shell 找不到 `bora`,重启终端,或检查安装目录是否在 PATH 上。

## 更新

Bora 会检查新版本并在应用内通知你。也可以手动更新:

```bash
bora update
```

`bora update` 适用于由 Bora 自带安装器管理的安装。Nix 安装请改用 Nix 更新。

Linux、macOS 和 Windows 的直接安装默认使用稳定更新通道。要启用来自 `main` 的预览构建,设置通道:

```bash
bora channel set preview
```

用同样的方式把直接安装切回稳定版:

```bash
bora channel set stable
```

对于直接安装,切换通道时也会检查该通道并安装其最新二进制文件。如果该更新失败,运行 `bora update` 从配置的通道重试。

预览构建是从当前开发分支定期发布的 GitHub 预发布。当你想在下一个稳定版之前拿到修复时很有用,但它们可能出现回归。Nix 安装不使用预览通道。

Windows 的常规使用建议选择稳定版。预览版能更早获得修复,但可能出现回归,因此只有在接受这一取舍时才应主动启用。现有的 Windows 预览安装会继续留在预览通道,直到你明确切换。如果旧预览构建拒绝 `bora channel set stable`,请先在预览通道运行一次 `bora update`,再重试切换通道。

默认情况下,`bora update` 会安装新二进制文件,并让端点第 1 代服务器及其窗格进程继续运行。再次启动 Bora 即可用更新后的客户端重新连接。纯客户端改动会立即生效。新的服务器端操作会保持不可用,直到对应服务器更新并重启;客户端会显示通知,而不会断开连接。只有早于端点第 1 代的服务器需要在更新时再停止最后一次。

要对受支持的运行中会话启用实验性的实时服务器交接,运行:

```bash
bora update --handoff
```

实时交接不适用于 Nix 的包管理器更新。这些安装先用 Nix 更新,再重新运行 Bora,用更新后的客户端连接。兼容的旧服务器会继续运行。只有需要新版本的服务器端改动时,才稍后用 `bora server stop` 或 `bora session stop <name>` 重启它。

## 系统要求

Linux、macOS 和 Windows x86_64 都提供稳定通道二进制文件。受支持的工作流和已知限制见 [Windows 支持](/zh-cn/docs/windows-beta/)。Windows ARM64 通过 Windows 模拟运行 x86_64 构建。
