---
title: Bora のインストール
description: Linux、macOS、Windows での Bora のインストール、アップデート、動作確認。
---

Bora は Linux、macOS、Windows 向けに安定版チャンネルのバイナリを提供しています。Windows 対応は正式提供されており、プラットフォーム固有の既知の制限と継続的な修正があります。

## インストール

Linux または macOS では次を実行します:

```bash
curl -fsSL https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.sh | sh
```

Windows では次を実行します:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 | iex"
```

エンドポイントセキュリティによってこのファイルレス PowerShell コマンドがブロックされる場合は、コマンドプロンプトを開いて次を実行します：

```cmd
curl.exe -fsSLo install.ps1 https://raw.githubusercontent.com/aryrabelo/bora-herdr-ada/main/distribution/install.ps1 && powershell -ExecutionPolicy Bypass -File install.ps1 && del install.ps1
```

インストーラーはプラットフォームに合ったリリースバイナリをダウンロードして PATH 上に配置します（Linux/macOS ではデフォルトで `~/.local/bin`、`HERDR_INSTALL_DIR` で上書き可能）。新しい直接インストールは安定版アップデートチャンネルを使います。既存の Windows プレビューインストールは、`bora channel set stable` で切り替えるまでプレビューに残ります。Windows では PATH が有効なバージョン付きリリースディレクトリを指し、インストーラーは互換性のため `current` と安定した `bin` エイリアスも更新します。そのため、アップデート時に実行中の `bora.exe` を上書きする必要がありません。

## Nix でインストール

すでに Nix を使っている場合、このリポジトリの flake はソースから Bora をビルドします:

```bash
nix run github:aryrabelo/bora-herdr-ada
nix build github:aryrabelo/bora-herdr-ada
nix profile install github:aryrabelo/bora-herdr-ada
```

flake は開発用シェルも公開しています:

```bash
nix develop github:aryrabelo/bora-herdr-ada
```

アップデートは、Bora のインストールに使ったのと同じ Nix ワークフローで行います。プロファイルインストールの場合は、プロファイルのエントリを一覧してエントリをアップグレードします:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

Bora が自分の flake の input になっている場合は、その input を更新してシステム、Home Manager、または開発環境を再ビルドします:

```bash
nix flake update bora
```

## 手動でダウンロード

[GitHub releases](https://github.com/aryrabelo/bora-herdr-ada/releases) からバイナリをダウンロードすることもできます。

システムに合ったアセットを選んでください:

| システム | アセット |
| --- | --- |
| Linux x86_64 | `bora-linux-x86_64` |
| Linux aarch64 | `bora-linux-aarch64` |
| macOS Intel | `bora-macos-x86_64` |
| macOS Apple silicon | `bora-macos-aarch64` |
| Windows x86_64 | `bora-windows-x86_64.zip` |

Linux または macOS では、実行可能にして PATH 上のどこかに移動します。

```bash
chmod +x bora-linux-x86_64
mv bora-linux-x86_64 ~/.local/bin/bora
```

### Windows アーカイブ

安定版リリースとプレビュープレリリースの両方に `bora-windows-x86_64.zip` が含まれます。アーカイブには `bora.exe` とアプリローカルの ConPTY ランタイムが含まれます。展開したディレクトリをまとめて保持し、`bora.exe` だけをコピーしないでください。

## 動作確認

Bora を起動します:

```bash
bora
```

シェルが `bora` を見つけられない場合は、ターミナルを再起動するか、インストール先ディレクトリが PATH に含まれているか確認してください。

## アップデート

Bora は新しいリリースをチェックし、アプリ内で通知します。手動でアップデートすることもできます:

```bash
bora update
```

`bora update` は Bora 自身のインストーラーで管理されているインストール向けです。Nix のインストールは Nix でアップデートしてください。

Linux、macOS、Windows の直接インストールは、デフォルトで安定版アップデートチャンネルを使います。`main` からのプレビュービルドにオプトインするには、チャンネルを設定します:

```bash
bora channel set preview
```

直接インストールを安定版に戻すのも同じ方法です:

```bash
bora channel set stable
```

直接インストールの場合、チャンネルの変更はそのチャンネルをチェックして最新バイナリをインストールします。そのアップデートが失敗した場合は、`bora update` を実行して設定済みチャンネルから再試行してください。

プレビュービルドは、現在の開発ブランチから定期的に公開される GitHub プレリリースです。次の安定版リリースより前に修正が欲しいときに便利ですが、リグレッションの可能性があります。Nix のインストールはプレビューチャンネルを使いません。

Windows の通常利用には安定版を推奨します。プレビューでは修正をより早く受け取れますが、リグレッションの可能性があるため、そのトレードオフを望む場合に限りオプトインしてください。既存の Windows プレビューインストールは、明示的に切り替えるまでプレビューに残ります。古いプレビュービルドで `bora channel set stable` が拒否される場合は、プレビューのまま一度 `bora update` を実行してから、チャンネル切り替えを再試行してください。

デフォルトでは、`bora update` は新しいバイナリをインストールし、エンドポイント世代 1 のサーバーとペインプロセスを動かしたままにします。再度 Bora を起動すると、更新済みクライアントで再接続します。クライアントだけの変更はすぐに使えます。新しいサーバー側アクションは、そのサーバーを更新して再起動するまで利用できず、クライアントは切断せずに通知を表示します。エンドポイント世代 1 より前のサーバーだけは、更新時に最後の 1 回の停止が必要です。

対応する実行中セッションで実験的なライブサーバーハンドオフにオプトインするには:

```bash
bora update --handoff
```

ライブハンドオフは Nix パッケージマネージャー経由のアップデートには適用されません。それらのインストールでは Nix で更新し、再度 Bora を実行して更新済みクライアントで再接続します。互換性のある古いサーバーは動き続けます。新しいリリースのサーバー側変更が必要になったときだけ、`bora server stop` または `bora session stop <name>` で後から再起動してください。

## 動作要件

安定版チャンネルのバイナリは Linux、macOS、Windows x86_64 で利用できます。サポートされるワークフローと既知の制限は [Windows サポート](/ja/docs/windows-beta/)を参照してください。Windows ARM64 では x86_64 ビルドが Windows のエミュレーション上で動作します。
